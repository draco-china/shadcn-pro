## Usage

```tsx
import { ProTable } from "@/components/pro/table"

const columns = [
  {
    accessorKey: "name",
    header: "Name",
    enableSorting: true,
    meta: { pinned: "left", search: { placeholder: "Search by name..." } },
  },
  { accessorKey: "email", header: "Email" },
  { accessorKey: "createdAt", header: "Created", meta: { pinned: "right" } },
]

export default function UsersTable() {
  return (
    <ProTable
      columns={columns}
      data={users}
      header={<h2 className="text-lg font-semibold">Users</h2>}
      table={{ stickyHeader: true }}
      toolbar={{
        filters: [
          {
            key: "created",
            render: () => <DateRangePicker value={range} onChange={setRange} />,
          },
        ],
        options: { refresh: () => refetch() },
      }}
    />
  )
}
```

`header` is reserved for title and description content. Search, filters, and actions belong in `toolbar`. Use `toolbar.filters` for business-specific controls such as keyword search, date ranges, and multi-field filters.

## Examples

### Pinned Columns and Sticky Header

Use `meta.pinned` on column definitions to keep important columns visible during horizontal scroll. Users can also pin or unpin columns from the column settings menu. System columns (`select`, `drag`, `actions`, `operation`) are pinned by default, use `w-8` by default, and are hidden from column settings; columns with `enableHiding: false` are also omitted from column settings. The table header is sticky by default; set `table={{ stickyHeader: false }}` to disable it.

```tsx
const columns = [
  { id: "select" },
  { accessorKey: "name", header: "Name", meta: { pinned: "left", className: "w-44" } },
  { accessorKey: "email", header: "Email", meta: { className: "w-60" } },
  { accessorKey: "createdAt", header: "Created", meta: { pinned: "right", className: "w-36" } },
]

<ProTable columns={columns} data={users} />
```

### Filtering with Reset

Add `meta.search` or `meta.filter` to columns — ProTable **automatically** renders the toolbar search input and `FacetedFilter` controls, maps `value → label` in cells, and shows a **Reset** button whenever any filter is active.

- Default filter behavior is **single-select**.
- Set `meta.filter.multiple: true` for multi-select filtering.

<ComponentPreview name="pro-table-filter-demo" previewClassName="min-h-[460px]" />

```tsx
const columns: ColumnDef<User>[] = [
  {
    accessorKey: "name",
    header: "Name",
    meta: {
      search: { placeholder: "Search name..." },
    },
  },
  {
    accessorKey: "role",
    header: "Role",
    meta: {
      filter: {
        placeholder: "Role",
        multiple: true,
        options: [
          { label: "Admin", value: "admin" },
          { label: "Editor", value: "editor" },
        ],
      },
    },
  },
  {
    accessorKey: "status",
    header: "Status",
    meta: {
      filter: {
        placeholder: "Status",
        variant: "text",
        options: [
          { label: "Active", value: "active" },
          { label: "Inactive", value: "inactive" },
        ],
      },
    },
  },
]

<ProTable
  columns={columns}
  data={data}
  toolbar={{
    filters: [
      {
        key: "createdAt",
        render: () => <DateRangePicker value={range} onChange={setRange} />,
      },
    ],
  }}
/>
```

`meta.search` writes to the same column filter state as the rest of the toolbar. Search columns use `@tanstack/match-sorter-utils` by default for fuzzy matching and rank-aware sorting in client-side tables. If you do not want to put search config in column meta, pass `toolbar={{ search: { columnId: "name", placeholder: "Search name..." } }}` instead; the target column gets the same default fuzzy behavior.

When `request` is provided, ProTable switches to manual filtering and sorting. Fuzzy matching is not run on the client; search/sort state is passed through to your request handler.

Internally ProTable dispatches from props: local `data` uses the client-side implementation, while `request` uses the server-side implementation. No extra prop is required.

Filtering, searching, and sorting reset pagination to the first page automatically.

### Request Data

`request` receives pagination, filters, and sorting. Return `{ data, total }`; you do not need to also pass `pagination.total`.

```tsx
<ProTable
  columns={columns}
  request={async ({ pagination, sorting, columnFilters }) => {
    const result = await api.users.list({
      page: pagination.pageIndex + 1,
      pageSize: pagination.pageSize,
      sort: sorting[0]?.id,
      order: sorting[0] ? (sorting[0].desc ? "desc" : "asc") : undefined,
      filters: columnFilters,
    })

    return {
      data: result.items,
      total: result.total,
    }
  }}
/>
```

When a column has `enableSorting: true`, clicking the header updates TanStack sorting state. With `useProTableUrlState`, it also syncs to `sort` / `order` URL params by default.

### Bulk Actions

Configure bottom-floating bulk actions when rows are selected. The floating toolbar supports keyboard navigation and `Escape` clears the selection.

```tsx
<ProTable
  columns={columns}
  data={users}
  bulkToolbar={{
    entityName: "user",
    actions: [
      {
        key: "export-selected",
        label: ({ selectedRows }) => `Export ${selectedRows.length}`,
        icon: <Download size={16} />,
        tooltip: "Export selected users",
        onClick: ({ table }) => table.resetRowSelection(),
      },
    ],
  }}
/>
```

### Drag-to-Sort

Enable row drag-to-sort with the `dragSort` object. Use `rowKey` to specify the unique identifier field and `onDragSortEnd` to receive the reordered data.

Drag sorting reorders the backing `data` array by the currently rendered rows. When the table is filtered or paginated, the dragged row moves relative to the visible target row in the original data array.

## API Reference

### ProTable

| Prop                    | Type                                  | Default                      | Description                                                                                                    |
| ----------------------- | ------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `columns`               | `ColumnDef<T>[]`                      | —                            | TanStack Table column definitions.                                                                             |
| `data`                  | `T[]`                                 | `[]`                         | Table data array for local/client data.                                                                        |
| `request`               | `(state) => Promise<{ data, total? }>`| —                            | Server request function. Return `{ data, total }`; `total` feeds pagination automatically.     |
| `initialState`          | `Partial<ProTableState>`              | —                            | Initial pagination, sorting, and column filters. Useful for URL-derived initial state.                          |
| `onChange`              | `(state) => void`                     | —                            | Called when pagination, sorting, or filters change. Useful for URL sync or manually loading data.               |
| `header`                | `ReactNode \| (context) => ReactNode` | —                            | Title/description area rendered above the toolbar. Do not put search, filters, or actions here.                                                                     |
| `toolbar`               | `false \| ProTableToolbarOptions<T>` | enabled                      | Toolbar config. Controls search, actions, and built-in options in one object.                                  |
| `toolbar.search`        | `false \| string \| { columnId, placeholder? }` | from `columns[].meta.search` | Explicit toolbar search config. Writes to the target column filter.                                  |
| `toolbar.filters`       | `ProToolbarItem<ProTableRenderContext<T>>[]` | — | Left-side custom toolbar controls, such as search boxes, date filters, and business filters. |
| `toolbar.options`       | `false \| { refresh?, density?, columns? }` | `{ density: true, columns: true }` | Built-in toolbar options, similar to Ant Design ProTable.                                           |
| `toolbar.actions`       | `ProTableAction<T>[]`                 | —                            | Configured toolbar action items rendered on the right side. |
| `toolbar.labels`        | `ProTableToolbarLabels`               | English defaults             | Override toolbar text such as search, reset, refresh, density, and columns. |
| `bulkToolbar`           | `false \| { entityName?, actions? }`  | —                            | Bulk toolbar config shown when rows are selected.                                                              |
| `pagination`            | `false \| { pageSizeOptions?, showTotal?, showQuickJump?, labels? }` | enabled                   | Pagination config. Set to `false` to hide pagination. `showTotal` and `showQuickJump` control secondary pagination UI. `labels` overrides pagination text for i18n. |
| `dragSort`              | `false \| { rowKey?, onDragSortEnd? }` | —                            | Drag sort config. Pass an object to enable row drag sorting.                                                   |
| `loading`               | `boolean \| { rows? }`                | `false`                      | Shows a skeleton loading state. Object form configures skeleton rows.                                           |
| `empty`                 | `{ text?, icon? }`                    | `{ text: 'No data' }`        | Empty state config for text and icon.                                                                          |
| `layout`                | `'full' \| 'auto'`                    | `'full'`                     | Full layout keeps pagination at the bottom with a spacer; the table itself still follows content height. |
| `table`                 | `{ stickyHeader?, pinning? }`         | `{ stickyHeader: true }`     | Table behavior config. `pinning` can be controlled with `{ value, onChange(value) }` or disabled with `false`.  |
| `className`             | `string`                              | —                            | Additional className for the outer container.                                                                  |

### Column Meta

| Meta                    | Type                                  | Default                      | Description                                                                                                    |
| ----------------------- | ------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `search`                | `boolean \| { placeholder? }`         | —                            | Enables the toolbar search input from this column.                                                             |
| `filter`                | `{ options, placeholder?, multiple?, variant?, onFilter? }` | —       | Auto-renders a FacetedFilter and maps values to labels in cells.                                                |
| `filter.options`        | `{ label, value }[]`                  | —                            | Options used by the auto-rendered FacetedFilter.                                                               |
| `filter.multiple`       | `boolean`                             | `false`                      | Whether the auto-rendered FacetedFilter returns multiple selected values.                                       |
| `filter.variant`        | `'badge' \| 'text'`                   | `'badge'`                    | Cell display style when `filter.options` is set.                                                               |
| `filter.onFilter`       | `(value, record) => boolean`          | auto                         | Custom matching function for advanced filter behavior.                                                         |
| `pinned`                | `'left' \| 'right'`                   | —                            | Initial pinned position for the column.                                                                        |
| `align`                 | `'left' \| 'center' \| 'right'`       | `'left'`                     | Aligns header and body cell content.                                                                           |
| `className`             | `string`                              | —                            | Class applied to header, body, and skeleton cells. Use width utilities like `w-32` or `min-w-40` when needed. Columns without explicit size or width classes stay auto-sized. |

### useProTableUrlState

Use URL search params as initial table state and sync later table state changes back to the URL — framework-agnostic via a `search` + `navigate` interface (compatible with TanStack Router, Next.js App Router, React Router, etc.).

```tsx
import { useProTableUrlState } from '@/components/pro/table/hooks/use-pro-table-url-state'

const urlState = useProTableUrlState({
  search: { page: 2, filter: 'alice' },  // current URL search params
  navigate: ({ search }) => { /* push new params to router */ },
})

<ProTable columns={columns} data={users} {...urlState} />
```

**Parameters:**

| Option          | Type            | Default      | Description                                      |
| --------------- | --------------- | ------------ | ------------------------------------------------ |
| `search`        | `SearchRecord`  | —            | Current URL search params as a plain object.     |
| `navigate`      | `NavigateFn`    | —            | Called with updated params to push to the router.|
| `pagination.pageKey`      | `string` | `'page'`    | URL key for current page.            |
| `pagination.pageSizeKey`  | `string` | `'pageSize'`| URL key for page size.               |
| `pagination.defaultPage`  | `number` | `1`         | Default page (omitted from URL).     |
| `pagination.defaultPageSize` | `number` | `10`     | Default page size (omitted from URL).|
| `sorting.sortKey` | `string` | `'sort'` | URL key for sorting column id. |
| `sorting.orderKey` | `string` | `'order'` | URL key for sort order (`asc` / `desc`). |
| `columnFilters` | `Array<ColumnFilterConfig>` | `[]`  | Column filter definitions with URL key mapping. |

**Returns:**

| Key                    | Type                          | Description                               |
| ---------------------- | ----------------------------- | ----------------------------------------- |
| `initialState`         | `Partial<ProTableState>`      | Pass to `<ProTable initialState={...} />`. |
| `onChange`             | `(state) => void`             | Pass to `<ProTable onChange={...} />`. |

**Example with Next.js App Router:**

```tsx
'use client'

import { useCallback, useMemo } from 'react'
import { useRouter, useSearchParams } from 'next/navigation'
import type { ColumnFilterConfig } from '@/components/pro/table/hooks/use-pro-table-url-state'
import { useProTableUrlState } from '@/components/pro/table/hooks/use-pro-table-url-state'
import { ProTable } from '@/components/pro/table'

const columnFilters: ColumnFilterConfig[] = [
  { columnId: 'name', searchKey: 'name' },
  { columnId: 'role', searchKey: 'role', type: 'array' },
]

export default function UsersTable() {
  const router = useRouter()
  const searchParams = useSearchParams()

  const search = useMemo(() => {
    const nextSearch: Record<string, string> = {}
    for (const [key, value] of searchParams.entries()) {
      nextSearch[key] = value
    }
    return nextSearch
  }, [searchParams])
  const navigate = useCallback(
    ({ search: next }) => {
      const params = new URLSearchParams()
      const resolved = typeof next === 'function' ? next(search) : next
      for (const key in resolved) {
        const value = resolved[key]
        if (value !== undefined) params.set(key, String(value))
      }
      router.push(`?${params.toString()}`)
    },
    [router, search],
  )

const tableState = useProTableUrlState({
  search,
  navigate,
  sorting: {
    sortKey: 'sort',
    orderKey: 'order',
  },
  columnFilters,
})

  return (
    <ProTable
      {...tableState}
      columns={columns}
      data={data}
    />
  )
}
```
