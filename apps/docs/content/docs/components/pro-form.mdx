## Usage

```tsx
import { createForm, ProForm } from "@/components/pro/form"

const form = createForm()
const schema = {
  type: "object",
  properties: {
    username: {
      type: "string",
      title: "Username",
      required: true,
      "x-component-props": { placeholder: "Enter username" },
    },
    email: {
      type: "string",
      title: "Email",
      required: true,
      "x-component-props": { type: "email", placeholder: "user@example.com" },
    },
  },
}

export default function BasicForm() {
  return (
    <ProForm form={form} schema={schema} onFinish={(values) => console.log(values)} />
  )
}
```

`ProForm` renders `schema` through the built-in `SchemaField`, so regular JSON schema forms do not need to import or render `<SchemaField>` manually. The schema renderer automatically fills common defaults:

- `string` → `Input`
- `number` / `integer` → `Digit`
- `boolean` → `Switch`
- `enum` → `Select`
- field schemas get `x-decorator: "FormItem"` unless explicitly configured

## Examples

### Validation

Real-time and async field validation with custom error messages.

<ComponentPreview name="pro-form-validation-demo" previewClassName="min-h-[480px]" />

Validation rules live in `schema` through Formily's field-level `required` and `x-validator`.
`ProForm` does not expose a separate `validationSchema` prop.
Use Formily's native validator syntax when you do not want an extra schema dependency:

```tsx
const schema = {
  type: "object",
  properties: {
    email: {
      type: "string",
      title: "Email",
      required: true,
      "x-validator": [
        { required: true, message: "Email is required" },
        { format: "email", message: "Please enter a valid email address" },
      ],
    },
    password: {
      type: "string",
      title: "Password",
      required: true,
      "x-validator": [
        { required: true, message: "Password is required" },
        { min: 8, message: "Password must be at least 8 characters" },
      ],
    },
  },
}
```

`x-validator` also accepts Zod schemas as an optional enhancement without making `ProForm` depend on `zod`. Use Zod's chainable API when a field has multiple Zod rules:

```tsx
import { z } from "zod"

const schema = {
  type: "object",
  properties: {
    email: {
      type: "string",
      title: "Email",
      required: true,
      "x-validator": z.string().email("Please enter a valid email address"),
    },
    password: {
      type: "string",
      title: "Password",
      required: true,
      "x-validator": z
        .string()
        .min(8, "Password must be at least 8 characters")
        .regex(/[A-Z]/, "Password must include an uppercase letter"),
    },
  },
}
```

### Schema-Driven

Define your entire form with a JSON schema. You can pass the schema directly to `ProForm`:

```tsx
import { ProForm } from "@/components/pro/form"

const schema = {
  type: "object",
  properties: {
    username: {
      type: "string",
      title: "Username",
      required: true,
      "x-validator": [{ required: true, message: "Username is required" }],
    },
    role: {
      type: "string",
      title: "Role",
      enum: [
        { label: "Admin", value: "admin" },
        { label: "User", value: "user" },
        { label: "Guest", value: "guest" },
      ],
    },
    notifications: {
      type: "boolean",
      title: "Enable notifications",
    },
  },
}

export default function SchemaForm() {
  return (
    <ProForm schema={schema} onFinish={(values) => console.log(values)} />
  )
}
```

Use `schemaComponents` when a schema references project-specific components:

```tsx
<ProForm
  schema={schema}
  schemaComponents={{
    UserPicker,
  }}
/>
```

When `enum` is present, `Select` options are inferred automatically and merged into
`x-component-props`; existing `x-component-props.options` are left unchanged.

### Reactions

Formily `x-reactions` are passed through unchanged, so conditional visibility and linkage can live in schema instead of React conditionals:

```tsx
const schema = {
  type: "object",
  properties: {
    type: {
      type: "string",
      title: "Type",
      enum: ["personal", "company"],
    },
    companyName: {
      type: "string",
      title: "Company Name",
      "x-reactions": {
        dependencies: ["type"],
        fulfill: {
          state: {
            visible: "{{$deps[0] === 'company'}}",
          },
        },
      },
    },
  },
}
```

### Header Submitter

```tsx
<ProForm
  submitter={{
    submit: { text: "保存", submittingText: "保存中..." },
    cancel: { text: "取消", onClick: () => router.back() },
    header: (actions) => (
      <div className="flex items-start justify-between border-b pb-4">
        <div>
          <h1 className="text-lg font-semibold">新增套餐</h1>
          <p className="text-sm text-muted-foreground">
            配置套餐基础信息、价格周期和节点授权。
          </p>
        </div>
        {actions}
      </div>
    ),
  }}
  onFinish={async (values) => {
    await createPackage(values)
  }}
>
  {/* fields */}
</ProForm>
```

`submitter.header` and `submitter.footer` receive the default actions node. Use them when a page needs title, description, tabs, status, or any custom layout around the built-in submit/cancel/reset buttons. When either slot is provided, only the explicit slot renders; otherwise the default actions render at `position`.

### Array Fields

Dynamic list of items with add/remove controls:

```ts
const schema = {
  type: "object",
  properties: {
    users: {
      type: "array",
      title: "Team Members",
      "x-component": "ArrayField",
      items: {
        type: "object",
        properties: {
          name: {
            type: "string",
            title: "Name",
          },
        },
      },
    },
  },
}
```

### Sections

Use `type: "void"` for section-only groups. Void sections do not create a form value and are rendered by the built-in `ProFormSection` by default:

```ts
const schema = {
  type: "object",
  properties: {
    basic: {
      type: "void",
      title: "Basic Information",
      "x-component-props": {
        columns: 2,
      },
      properties: {
        firstName: { type: "string", title: "First Name" },
        lastName: { type: "string", title: "Last Name" },
      },
    },
  },
}
```

When `x-component` is set explicitly, that component is used instead of the default `ProFormSection` inference.

`ProFormSection` is a form layout section, not an object value field. Non-root `type: "object"` groups are rendered by the built-in `ObjectField` by default, while the root schema object stays unwrapped.

When composing with `SchemaField` JSX instead of the `schema` prop, set `x-component="ProFormSection"` explicitly because JSX fields do not run through schema normalization.

```tsx
<SchemaField.Void
  title="Basic Information"
  x-component="ProFormSection"
  x-component-props={{ columns: 2 }}
>
  <SchemaField.String name="firstName" title="First Name" />
  <SchemaField.String name="lastName" title="Last Name" />
</SchemaField.Void>
```

If the root form body should also render as a section, set the root schema component explicitly:

```ts
const schema = {
  type: "object",
  title: "Basic Information",
  "x-component": "ProFormSection",
  "x-component-props": {
    columns: 2,
  },
  properties: {
    firstName: { type: "string", title: "First Name" },
    lastName: { type: "string", title: "Last Name" },
  },
}
```

### Object Fields

Use `type: "object"` when the group should produce an object value. Nested object groups are rendered by the built-in `ObjectField` automatically:

```ts
const schema = {
  type: "object",
  properties: {
    address: {
      type: "object",
      title: "Address",
      properties: {
        city: { type: "string", title: "City" },
        street: { type: "string", title: "Street" },
      },
    },
  },
}
```

### Field Tooltip and Extra

`FormItem` follows Formily's decorator semantics: `tooltip` renders as the info icon beside the label, while `extra` renders helper text below the field. Schema `description` also renders as the label tooltip, and an explicit `tooltip` takes priority.

```tsx
<ProForm
  schema={{
    type: "object",
    properties: {
      email: {
        type: "string",
        title: "Email",
        required: true,
        description: "We will never share your email with anyone.",
        "x-component-props": { placeholder: "user@example.com" },
      },
      bio: {
        type: "string",
        title: "Bio",
        "x-component": "Textarea",
        "x-decorator-props": {
          tooltip: "Shown on your public profile.",
          extra: "Max 200 characters.",
        },
      },
    },
  }}
/>
```

### Manual SchemaField

`SchemaField` is still exported for advanced JSX composition or local recursive rendering. Prefer `ProForm schema={schema}` for normal JSON schema forms.

## API Reference

### ProForm

| Prop | Type | Default | Description |
|---|---|---|---|
| `form` | `Form` | internal form | Formily form instance created with `createForm()`. Omit to let `ProForm` create one. |
| `formProps` | `IFormProps` | — | Options used when `ProForm` creates the internal form. |
| `schema` | `ISchema` | — | JSON schema rendered by the built-in schema field. Defaults are inferred for common field types. |
| `schemaComponents` | `SchemaReactComponents` | — | Extra components available to JSON schema. |
| `children` | `ReactNode` | — | Form fields and layout components. |
| `onFinish` | `(values) => void \| Promise<void>` | — | Called after successful validation. |
| `onFinishFailed` | `(errors) => void` | — | Called when validation fails on submit. |
| `onReset` | `() => void \| Promise<void>` | — | Called after reset completes. |
| `submitter` | `false \| ProFormSubmitterProps` | `{}` | Built-in submitter config. Set to `false` to hide actions. |
| `columns` | `1 \| 2 \| 3 \| 4` | — | Multi-column layout for the top-level form body. |
| `gap` | `string` | `'gap-4'` | Tailwind gap class for the top-level form body or root section content. |
| `className` | `string` | — | Additional className for the `<form>` element. |

### ProFormSubmitter

Object config for the built-in submit/cancel/reset area. `header` renders above the form and `footer` renders below it; both receive the default actions node.

Default action priority is explicit and uses the underlying button variants directly: submit defaults to `default`, cancel defaults to `outline`, and reset defaults to `secondary`. Override each button with `submit.variant`, `cancel.variant`, or `reset.variant`.

| Prop | Type | Default | Description |
|---|---|---|---|
| `position` | `'header' \| 'footer'` | `'footer'` | Where default actions render when no `header` or `footer` slot is provided. |
| `submit` | `false \| ProFormSubmitActionProps` | `{}` | Submit button config. Set `false` or `hidden: true` to hide it. |
| `cancel` | `false \| ProFormCancelActionProps` | — | Cancel button config. Omit to hide it. |
| `reset` | `false \| ProFormResetActionProps` | — | Reset button config. Omit to hide it. |
| `submitting` | `boolean` | — | Controlled submitting state for default actions. |
| `loading` | `boolean` | `false` | Fallback loading state for default actions. |
| `className` | `string` | — | Additional className for the default actions node. |
| `header` | `ReactNode \| (actions, context) => ReactNode` | — | Custom header submitter slot. |
| `footer` | `ReactNode \| (actions, context) => ReactNode` | default footer renderer | Custom footer submitter slot. |

### ProFormBody

Shared form body layout used by `ProForm`, `ModalForm`, and `DrawerForm`. It renders a root `ProFormSection` when the root schema declares `x-component: "ProFormSection"` or a root `type: "void"` schema with properties, otherwise it renders a grid body directly.

| Prop | Type | Default | Description |
|---|---|---|---|
| `schema` | `ISchema` | — | Optional schema used to detect root section metadata. |
| `columns` | `1 \| 2 \| 3 \| 4` | — | Responsive grid columns for body content. |
| `gap` | `string` | `'gap-4'` | Tailwind gap class for body content. |
| `className` | `string` | — | Additional className for the rendered body or root section. |
| `children` | `ReactNode` | — | Form body content. |

### ProFormSection

Section-only layout container used by `type: "void"` schema groups.

| Prop | Type | Default | Description |
|---|---|---|---|
| `title` | `ReactNode` | field title | Section heading. |
| `description` | `ReactNode` | field description | Helper text below the heading. |
| `action` | `ReactNode` | — | Element rendered to the right of the heading. |
| `columns` | `1 \| 2 \| 3 \| 4` | — | Render section content as a responsive grid. |
| `gap` | `string` | `'gap-4'` | Tailwind gap class for the section content grid. |
| `className` | `string` | — | Additional className for the section. |
| `contentClassName` | `string` | — | Additional className for the section content. |
