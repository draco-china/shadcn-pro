## Usage

```tsx
import { createForm, ProForm } from "@/components/pro/pro-form"

const form = createForm()
const schema = {
  type: "object",
  properties: {
    username: {
      type: "string",
      title: "Username",
      required: true,
      "x-component-props": { placeholder: "Enter username" },
    },
    email: {
      type: "string",
      title: "Email",
      required: true,
      "x-component-props": { type: "email", placeholder: "user@example.com" },
    },
  },
}

export default function BasicForm() {
  return (
    <ProForm form={form} schema={schema} onFinish={(values) => console.log(values)} />
  )
}
```

`ProForm` renders `schema` through the built-in `SchemaField`, so regular JSON schema forms do not need to import or render `<SchemaField>` manually. The schema renderer automatically fills common defaults:

- `string` → `Input`
- `number` / `integer` → `Digit`
- `boolean` → `Switch`
- `enum` → `Select`
- field schemas get `x-decorator: "FormItem"` unless explicitly configured

### Schema-Driven

Define your entire form with a JSON schema. You can pass the schema directly to `ProForm`:

```tsx
import { ProForm } from "@/components/pro/pro-form"

const schema = {
  type: "object",
  properties: {
    username: {
      type: "string",
      title: "Username",
      required: true,
      "x-validator": [{ required: true, message: "Username is required" }],
    },
    role: {
      type: "string",
      title: "Role",
      enum: [
        { label: "Admin", value: "admin" },
        { label: "User", value: "user" },
        { label: "Guest", value: "guest" },
      ],
    },
    notifications: {
      type: "boolean",
      title: "Enable notifications",
    },
  },
}

export default function SchemaForm() {
  return (
    <ProForm schema={schema} onFinish={(values) => console.log(values)} />
  )
}
```

Use `schemaComponents` when a schema references project-specific components:

```tsx
<ProForm
  schema={schema}
  schemaComponents={{
    UserPicker,
  }}
/>
```

### Reactions

Formily `x-reactions` are passed through unchanged, so conditional visibility and linkage can live in schema instead of React conditionals:

```tsx
const schema = {
  type: "object",
  properties: {
    type: {
      type: "string",
      title: "Type",
      enum: ["personal", "company"],
    },
    companyName: {
      type: "string",
      title: "Company Name",
      "x-reactions": {
        dependencies: ["type"],
        fulfill: {
          state: {
            visible: "{{$deps[0] === 'company'}}",
          },
        },
      },
    },
  },
}
```

### Header Submitter

```tsx
<ProForm
  submitter={{
    submit: { text: "保存", submittingText: "保存中..." },
    cancel: { text: "取消", onClick: () => router.back() },
    header: (actions) => (
      <div className="flex items-start justify-between border-b pb-4">
        <div>
          <h1 className="text-lg font-semibold">新增套餐</h1>
          <p className="text-sm text-muted-foreground">
            配置套餐基础信息、价格周期和节点授权。
          </p>
        </div>
        {actions}
      </div>
    ),
  }}
  onFinish={async (values) => {
    await createPackage(values)
  }}
>
  {/* fields */}
</ProForm>
```

`submitter.header` and `submitter.footer` receive the default actions node. Use them when a page needs title, description, tabs, status, or any custom layout around the built-in submit/cancel/reset buttons.

### Array Fields

Dynamic list of items with add/remove controls:

```ts
const schema = {
  type: "object",
  properties: {
    users: {
      type: "array",
      title: "Team Members",
      "x-component": "ArrayField",
      items: {
        type: "object",
        properties: {
          name: {
            type: "string",
            title: "Name",
          },
        },
      },
    },
  },
}
```

### Object Fields

Nested object grouping with optional card wrapper:

const schema = {

### Field Tooltip and Extra

`FormItem` follows Formily's decorator semantics: `tooltip` renders as the info icon beside the label, while `extra` renders helper text below the field. Schema `description` also renders as the label tooltip, and an explicit `tooltip` takes priority.

```tsx
<ProForm
  schema={{
    type: "object",
    properties: {
      email: {
        type: "string",
        title: "Email",
        required: true,
        description: "We will never share your email with anyone.",
        "x-component-props": { placeholder: "user@example.com" },
      },
      bio: {
        type: "string",
        title: "Bio",
        "x-component": "Textarea",
        "x-decorator-props": {
          tooltip: "Shown on your public profile.",
          extra: "Max 200 characters.",
        },
      },
    },
  }}
/>
```

### Manual SchemaField

`SchemaField` is still exported for advanced JSX composition or local recursive rendering. Prefer `ProForm schema={schema}` for normal JSON schema forms.

## API Reference

### ProForm

| Prop | Type | Default | Description |
|---|---|---|---|
| `form` | `Form` | internal form | Formily form instance created with `createForm()`. Omit to let `ProForm` create one. |
| `formProps` | `IFormProps` | — | Options used when `ProForm` creates the internal form. |
| `schema` | `ISchema` | — | JSON schema rendered by the built-in schema field. Defaults are inferred for common field types. |
| `schemaComponents` | `SchemaReactComponents` | — | Extra components available to JSON schema. |
| `children` | `ReactNode` | — | Form fields and layout components. |
| `onFinish` | `(values) => void \| Promise<void>` | — | Called after successful validation. |
| `onFinishFailed` | `(errors) => void` | — | Called when validation fails on submit. |
| `onReset` | `() => void \| Promise<void>` | — | Called after reset completes. |
| `submitter` | `false \| ProFormSubmitterProps` | `{}` | Built-in submitter config. Set to `false` to hide actions. |
| `columns` | `1 \| 2 \| 3 \| 4` | — | Multi-column layout. Wraps fields in `ProFormGrid` automatically. |
| `className` | `string` | — | Additional className for the `<form>` element. |

### ProFormSubmitter

Object config for the built-in submit/cancel/reset area. `header` renders above the form and `footer` renders below it; both receive the default actions node.

| Prop | Type | Default | Description |
|---|---|---|---|
| `position` | `'header' \| 'footer'` | `'footer'` | Where default actions render when no `header` slot is provided. |
| `submit` | `false \| ProFormSubmitActionProps` | `{}` | Submit button config. Set `false` or `hidden: true` to hide it. |
| `cancel` | `false \| ProFormCancelActionProps` | — | Cancel button config. Omit to hide it. |
| `reset` | `false \| ProFormResetActionProps` | — | Reset button config. Omit to hide it. |
| `submitting` | `boolean` | — | Controlled submitting state for default actions. |
| `loading` | `boolean` | `false` | Fallback loading state for default actions. |
| `actionsVariant` | `'page' \| 'inline' \| 'overlay'` | header: `'page'`, footer: `'inline'` | Visual variant for actions. |
| `align` | `'left' \| 'center' \| 'right'` | header: `'right'`, footer: `'left'` | Alignment of default actions. |
| `header` | `ReactNode \| (actions, context) => ReactNode` | — | Custom header submitter slot. |
| `footer` | `ReactNode \| (actions, context) => ReactNode` | default footer renderer | Custom footer submitter slot. |

### ProFormGrid

Multi-column grid container — fields inside are evenly distributed.

| Prop | Type | Default | Description |
|---|---|---|---|
| `columns` | `1 \| 2 \| 3 \| 4` | `1` | Number of columns. |
| `gap` | `string` | `'gap-4'` | Tailwind gap class. |
| `className` | `string` | — | Additional className. |

### ProFormActions

Standalone action bar — use directly when a page needs to compose actions outside `ProForm`.

| Prop | Type | Default | Description |
|---|---|---|---|
| `submit` | `false \| ProFormSubmitActionProps` | `{}` | Submit button config. |
| `cancel` | `false \| ProFormCancelActionProps` | — | Cancel button config. |
| `reset` | `false \| ProFormResetActionProps` | — | Reset button config. |
| `submitting` | `boolean` | — | Controlled submitting state. |
| `loading` | `boolean` | `false` | Fallback loading state. |
| `actionsVariant` | `'page' \| 'inline' \| 'overlay'` | `'inline'` | Visual variant for page header, inline, or overlay footer actions. |
| `align` | `'left' \| 'center' \| 'right'` | `'left'` | Alignment of buttons. |
| `children` | `ReactNode` | — | Extra buttons or content to render alongside actions. |

### ModalForm

A `ProForm` embedded inside a shadcn `Dialog`. The dialog opens when the `trigger` is clicked and closes automatically on successful submit.

| Prop | Type | Default | Description |
|---|---|---|---|
| `trigger` | `ReactNode` | — | Optional element that opens the dialog on click. Omit for controlled open mode. |
| `title` | `string` | — | Dialog title. |
| `description` | `string` | — | Optional subtitle shown below the title. |
| `schema` | `ISchema` | — | JSON schema rendered inside the form. |
| `schemaComponents` | `SchemaReactComponents` | — | Extra schema components. |
| `open` | `boolean` | — | Controlled open state. |
| `onOpenChange` | `(open: boolean) => void` | — | Controlled open state handler. |
| `onFinish` | `(values) => void \| Promise<void>` | — | Called after successful validation. Dialog closes on resolve. |
| `onFinishFailed` | `(errors) => void` | — | Called when validation fails. Dialog stays open. |
| `submitter` | `false \| OverlayFormSubmitterProps` | `{}` | Submitter config. Set `false` to hide footer actions. |
| `form` | `Form` | internal | Formily form instance. |
| `formProps` | `IFormProps` | — | Options when creating the internal form. |
| `columns` | `1 \| 2 \| 3 \| 4` | — | Multi-column layout. |
| `widthClass` | `string` | `'sm:max-w-lg'` | Tailwind class controlling dialog width. |
| `className` | `string` | — | Additional className for the form element. |
| `children` | `ReactNode` | — | Form fields (`SchemaField` nodes or layout components). |

### DrawerForm

Identical to `ModalForm` but renders inside a shadcn `Drawer` that slides in from a screen edge.

| Prop | Type | Default | Description |
|---|---|---|---|
| `trigger` | `ReactNode` | — | Optional element that opens the drawer on click. Omit for controlled open mode. |
| `title` | `string` | — | Drawer title. |
| `description` | `string` | — | Optional subtitle shown below the title. |
| `schema` | `ISchema` | — | JSON schema rendered inside the form. |
| `schemaComponents` | `SchemaReactComponents` | — | Extra schema components. |
| `side` | `'right' \| 'left' \| 'top' \| 'bottom'` | `'right'` | Which edge the drawer slides in from. |
| `open` | `boolean` | — | Controlled open state. |
| `onOpenChange` | `(open: boolean) => void` | — | Controlled open state handler. |
| `onFinish` | `(values) => void \| Promise<void>` | — | Called after successful validation. Drawer closes on resolve. |
| `onFinishFailed` | `(errors) => void` | — | Called when validation fails. Drawer stays open. |
| `submitter` | `false \| OverlayFormSubmitterProps` | `{}` | Submitter config. Set `false` to hide footer actions. |
| `form` | `Form` | internal | Formily form instance. |
| `formProps` | `IFormProps` | — | Options when creating the internal form. |
| `columns` | `1 \| 2 \| 3 \| 4` | — | Multi-column layout. |
| `className` | `string` | — | Additional className for the form element. |
| `children` | `ReactNode` | — | Form fields (`SchemaField` nodes or layout components). |
