## Prerequisites

Before installing shadcn-pro, make sure you have:

- **Node.js 18+** (or Bun / pnpm)
- A Next.js project (or any React framework) with **shadcn/ui already initialized**

<Callout>
  If you haven't set up shadcn/ui yet, follow the [shadcn/ui installation guide](https://ui.shadcn.com/docs/installation) first, then come back here.
</Callout>

## Authentication

shadcn-pro is published to **GitHub Packages**, so installing the CLI requires a GitHub token that can read packages.

Create a GitHub personal access token with the `read:packages` scope. If the package or repository is private, the token must also have access to that repository.

Export the token in your shell:

```bash
export GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
```

Then add the GitHub Packages registry and auth token to your project's `.npmrc`:

```bash
# .npmrc (project root)
@draco-china:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

<Callout>
  Do not commit a real token into `.npmrc`. Keep the file using the `${GITHUB_TOKEN}` environment variable, or use your package manager's local/user-level auth configuration.
</Callout>

You can also authenticate with npm directly:

```bash
npm login --scope=@draco-china --registry=https://npm.pkg.github.com
```

Use your GitHub username and the token as the password.

## Initialization

Then add components with the CLI:

```bash
npx @draco-china/shadcn-pro@latest add pro-form
```

This copies the component source code directly into your project under `components/pro/`.

## Using the CLI

The recommended way to add components is through the shadcn-pro registry CLI. Manual copying is only for debugging or for projects that cannot run the registry installer.

List available components first when you are exploring:

```bash
npx @draco-china/shadcn-pro@latest list
```

Then add any component by name:

```bash
npx @draco-china/shadcn-pro@latest add pro-base
```

```bash
npx @draco-china/shadcn-pro@latest add pro-fields
```

```bash
npx @draco-china/shadcn-pro@latest add pro-form
```

```bash
npx @draco-china/shadcn-pro@latest add pro-table
```

```bash
npx @draco-china/shadcn-pro@latest add markdown-viewer
```

## Manual Installation

### 1. Install dependencies

Install the dependencies for the component you copy:

| Component | Dependencies |
| --- | --- |
| `pro-base` | `lucide-react` |
| `pro-fields` | `@dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities date-fns lucide-react` |
| `pro-form` | `@formily/core @formily/react @formily/reactive-react date-fns lucide-react` |
| `pro-table` | `@tanstack/react-table @tanstack/match-sorter-utils @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities lucide-react` |
| `pro-editor` | `@monaco-editor/react @shikijs/monaco monaco-editor shiki lucide-react` |
| `pro-descriptions` | `lucide-react` through `pro-base` |
| `pro-input` | `lucide-react` |
| `code-viewer` | `shiki lucide-react` |
| `diff-viewer` | `diff shiki` |
| `html-viewer` | None |
| `image-viewer` | `lucide-react` |
| `markdown-viewer` | `react-markdown shiki lucide-react remark-gfm remark-breaks remark-math remark-toc rehype-raw rehype-sanitize rehype-mathjax` |

For example:

```bash
bun add react-markdown shiki lucide-react remark-gfm remark-breaks remark-math remark-toc rehype-raw rehype-sanitize rehype-mathjax
```

### 2. Copy the component

Browse the component source on GitHub and copy each component folder into your project. Prefer the registry installer because it also copies shared Pro dependencies and internal registry dependencies such as `pro-toolbar`.

- `ProBase` → `components/pro/base/`
- `ProFields` → `components/pro/base/fields/`
- `ProForm` → `components/pro/form/`
- `ProTable` → `components/pro/table/`
- `ProEditor` → `components/pro/editor/`
- `ProDescriptions` → `components/pro/descriptions/` and `components/pro/base/`
- `CodeViewer` → `components/pro/viewer/code/`
- `DiffViewer` → `components/pro/viewer/diff/`
- `HtmlViewer` → `components/pro/viewer/html/`
- `ImageViewer` → `components/pro/viewer/image/`
- `MarkdownViewer` → `components/pro/viewer/markdown/index.tsx` and `components/pro/viewer/code/`

`ProInput` is a focused subset of ProFields. Copy `components/pro/base/fields/input/`, `components/pro/base/fields/password/`, and the shared field helpers they import.

### 3. Import and use

```tsx
import { Input } from "@/components/pro/base/fields/input"
import { ProForm } from "@/components/pro/form"
import { ProTable } from "@/components/pro/table"
```

## Standard Patterns

### Request + hooks/store

Use `request` to keep existing API hooks or stores outside the table component while still letting ProTable own pagination, filters, and sorting.

```tsx
<ProTable
  columns={columns}
  request={({ pagination, sorting, columnFilters }) =>
    userStore.fetchUsers({
      page: pagination.pageIndex + 1,
      pageSize: pagination.pageSize,
      sort: sorting[0]?.id,
      order: sorting[0] ? (sorting[0].desc ? "desc" : "asc") : undefined,
      filters: columnFilters,
    })
  }
/>
```

The request result should be `{ data, total }`.

### URL state

```tsx
const tableState = useProTableUrlState({
  search,
  navigate,
  sorting: { sortKey: "sort", orderKey: "order" },
  columnFilters: [
    { columnId: "name", searchKey: "name" },
    { columnId: "role", searchKey: "role", type: "array" },
  ],
})

<ProTable columns={columns} request={request} {...tableState} />
```

### JSON schema forms

```tsx
<ProForm
  schema={{
    type: "object",
    properties: {
      name: { type: "string", title: "Name" },
      age: { type: "number", title: "Age" },
      enabled: { type: "boolean", title: "Enabled" },
      role: { type: "string", title: "Role", enum: ["admin", "user"] },
    },
  }}
/>
```

Use Formily `x-reactions` for conditional visibility and linkage. `ModalForm` and `DrawerForm` accept the same `schema` and `schemaComponents` props, and can be controlled with `open` / `onOpenChange` without a trigger.

## TypeScript

shadcn-pro is written in TypeScript. All components are fully typed.

## Tailwind CSS

shadcn-pro uses Tailwind CSS v4 classes and inherits your shadcn/ui theme tokens. No additional configuration is needed.
