## Prerequisites

Before installing shadcn-pro, make sure you have:

- **Node.js 18+** (or Bun / pnpm)
- A Next.js project (or any React framework) with **shadcn/ui already initialized**

<Callout>
  If you haven't set up shadcn/ui yet, follow the [shadcn/ui installation guide](https://ui.shadcn.com/docs/installation) first, then come back here.
</Callout>

## Initialization

shadcn-pro is published to **GitHub Packages**. Add the registry to your project's `.npmrc`:

```bash
# .npmrc (project root)
@draco-china:registry=https://npm.pkg.github.com
```

Then add components with the CLI:

```bash
npx @draco-china/shadcn-pro@latest add pro-form
```

This copies the component source code directly into your project under `components/pro/`.

## Using the CLI

The recommended way to add components is through the shadcn-pro registry CLI. Manual copying is only for debugging or for projects that cannot run the registry installer.

List available components first when you are exploring:

```bash
npx @draco-china/shadcn-pro@latest list
```

Then add any component by name:

```bash
npx @draco-china/shadcn-pro@latest add pro-fields
```

### 2. Copy the component

Browse the component source on GitHub and copy each component folder into your project. Prefer the registry installer because it also copies internal registry dependencies such as `pro-base` and `pro-toolbar`.

- `ProBase` → `components/pro/pro-base/`
- `ProToolbar` → `components/pro/pro-toolbar/`
- `ProFields` → `components/pro/pro-fields/`
- `ProForm` → `components/pro/pro-form/`
- `ProTable` → `components/pro/pro-table/`
- `ProEditor` → `components/pro/pro-editor/`
- `ProDescriptions` → `components/pro/pro-descriptions/`
- `CodeViewer` → `components/pro/pro-viewer/code/`
- `DiffViewer` → `components/pro/pro-viewer/diff/`
- `HtmlViewer` → `components/pro/pro-viewer/html/`
- `ImageViewer` → `components/pro/pro-viewer/image/`
- `MarkdownViewer` → `components/pro/pro-viewer/markdown/index.tsx` and `components/pro/pro-viewer/code/`

`ProInput` is a focused subset of ProFields. Copy `components/pro/pro-fields/input.tsx` and `components/pro/pro-fields/password.tsx`.

## Standard Patterns

### Request + hooks/store

Use `request` to keep existing API hooks or stores outside the table component while still letting ProTable own pagination, filters, and sorting.

```tsx
<ProTable
  columns={columns}
  request={({ pagination, sorting, columnFilters }) =>
    userStore.fetchUsers({
      page: pagination.pageIndex + 1,
      pageSize: pagination.pageSize,
      sort: sorting[0]?.id,
      order: sorting[0] ? (sorting[0].desc ? "desc" : "asc") : undefined,
      filters: columnFilters,
    })
  }
/>
```

The request result should be `{ data, total }`.

### URL state

```tsx
const tableState = useProTableUrlState({
  search,
  navigate,
  sorting: { sortKey: "sort", orderKey: "order" },
  columnFilters: [
    { columnId: "name", searchKey: "name" },
    { columnId: "role", searchKey: "role", type: "array" },
  ],
})

<ProTable columns={columns} request={request} {...tableState} />
```

### JSON schema forms

```tsx
<ProForm
  schema={{
    type: "object",
    properties: {
      name: { type: "string", title: "Name" },
      age: { type: "number", title: "Age" },
      enabled: { type: "boolean", title: "Enabled" },
      role: { type: "string", title: "Role", enum: ["admin", "user"] },
    },
  }}
/>
```

Use Formily `x-reactions` for conditional visibility and linkage. `ModalForm` and `DrawerForm` accept the same `schema` and `schemaComponents` props, and can be controlled with `open` / `onOpenChange` without a trigger.

## TypeScript

shadcn-pro is written in TypeScript. All components are fully typed.

## Tailwind CSS

shadcn-pro uses Tailwind CSS v4 classes and inherits your shadcn/ui theme tokens. No additional configuration is needed.
